## 目的
- 仕様書が増減しても「どこに何があるか」を短く把握できるようにする。

---

## 推奨する読み方（ルール）

- 初見は `docs/_INDEX.md` → `仕様書一式/` の順に辿る
- 仕様書一式の中では、次の順で読むのを推奨：
  1) プロジェクト全体ルール（運用/設計の統一）
  2) 設定・入出力（I/O）の正本
  3) コア機能（Collector等）
  4) 横断機能（Rate/Health/Supervisor等）
  5) バックアップ・復旧・監査

## 一覧（自動生成に寄せる）

ファイルが増減する前提なので、ここに **固定の列挙はしない**。
代わりに以下のどちらかを採用：

- **A. 手動最小**：重要な数本だけリンクを貼る（最大 5〜8 本）
- **B. 自動**：Utilities の `DOCS_INDEX.md` へのリンクを貼り、最新一覧はそちらで確認

例（Bを推奨）
