# BTC TS Next / Docs

## このディレクトリについて（必読）

この `docs/` ディレクトリは **BTC TS Next プロジェクトの設計・仕様・引き継ぎ情報の正準置き場** です。

ここに配置される文書は、以下の役割分担に基づいて管理します。

---

## 正準（最優先）

以下は **実装判断・開発継続時に最優先で参照される正準文書** です。

* `handover.md`

  * 現在の開発状態・前提・次タスクを記した引き継ぎ文書
  * GPT との継続開発時は **必ず最初に読む**

* 本リポジトリ内の **現物コード**

  * 文書とコードが矛盾した場合、最終的な正はコードとする

---

## working/（編集中・設計途中）

```
docs/working/
```

* 設計途中・検討中・将来変更される前提の文書を配置
* GPT との設計議論・要件整理・構造検討はすべてここに置く
* **破壊・書き換え前提**。完成した仕様はここに置き続けない

例：

* `requirements_from_v1.md`

  * V1 仕様書を参考に抽出した NEXT 用の要件メモ
  * 参考資料であり、正準仕様ではない

---

## 仕様書一式/（完成・凍結）

```
docs/仕様書一式/
```

* 実装方針・仕様が固まり「完成」と判断した文書を配置
* 原則として **変更しない**（変更が必要な場合は working で再検討）
* 将来の自分・第三者・別 GPT への説明用

例：

* `collector_spec.md`
* `health_spec.md`
* `dashboard_spec.md`
* `audit_spec.md`

---

## 旧仕様書（V1）について

* V1 の仕様書・設計資料は **参考資料** として扱う
* **git 管理外**（例：`_stash/Docs` 等）に隔離する
* 本リポジトリ内に V1 の原本を復活させない
* NEXT 実装時に混同・逆流させないことを最優先とする

---

## 命名・表記ルール

* Markdown / TXT のみを使用（バイナリ・バイトコード不可）
* フォルダ名・ファイル名は日本語可（例：`仕様書一式`）
* 内容が明確であれば 2 バイト文字の使用は問題なし

---

## GPT との開発時の注意

* 推測での実装提案は禁止
* 修正は **必ず現物コードを確認した上で**行う
* 1ファイル1キャンバスの原則を遵守
* 本 README に反する運用は行わない

---

に存在します。
